# Bot P1/P2 Fixes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add the remaining P1/P2 bot fixes on top of the P0 case-isolation/image work: post-verdict action steps, accuracy calibration, never-silent error handling, and regression tests for items already satisfied by P0.

**Architecture:** All changes are in the existing bot pipeline. Action steps and fallbacks are new templated strings in `formatter.ts`, wired in `bot.ts`/`index.ts`. Calibration tightens one over-broad heuristic pattern and adds few-shot anchors to the OpenAI prompt. Tests use the existing `node:assert` harness.

**Tech Stack:** TypeScript (NodeNext), Node 22 `fetch`, `node:assert` tests via `npm run bot:test`.

## Global Constraints

- Builds on branch `feat/bot-fixes-p0` (case isolation + `images[]` + `buildContent` already present).
- NodeNext `.js` imports; commit only `bot/src/*`; no new dependencies.
- Risk label/header stay rendered from code templates in `formatter.ts` (never model free-text).
- LOW / no-risk is a first-class outcome with no forced reasons.
- The bot must never go silent: every inbound that reaches processing either replies or sends a friendly fallback.

- [ ] **Step 2: Run to verify failure** — `npm run bot:build && node bot/dist/taxonomy.test.js`. Expected: first assertion fails (love_bombing currently matches "my wife").

- [ ] **Step 3: Tighten the love-bombing pattern in `taxonomy.ts`** — in the `love_bombing` rule, change the first pattern from:
```ts
      /\b(soulmate|my queen|my king|my wife|my husband|i love you|marry you|destiny|meant to be)\b/i,
```
to (drop the ambiguous standalone `my wife|my husband` — they match talk *about* a wife, not affection *toward the chat partner*; keep the clear endearments):
```ts
      /\b(soulmate|my queen|my king|i love you|marry you|destiny|meant to be|my love|my darling)\b/i,
```

- [ ] **Step 4: Strengthen the OpenAI prompt** — append few-shot anchors to the `systemPrompt` string in `openai-analyzer.ts` (before the closing backtick):
```
Examples:
- "I love you, you're my soulmate, send me $300 in Steam cards, my camera is broken" -> HIGH (love_bombing + money_or_gift_card_or_crypto_request + video_or_voice_call_avoidance, each with a quote).
- "lol when I'm rich I'll buy a GLE for my wife" -> LOW, reasons: [] (joking about a car; "my wife" is not affection toward the user).
- "Had a good day at work, watched a movie, talked about our families" -> LOW, reasons: [] (ordinary friendly chat).
Only include a signal when you can quote text that genuinely supports THAT signal. An ordinary, friendly conversation with no signals must be LOW with an empty reasons list.
```

### Task 3: Never go silent (error fallback)

**Files:**
- Modify: `bot/src/formatter.ts` (new `overloadedMessage()`)
- Modify: `bot/src/openai-analyzer.ts` (one retry with backoff on 429/5xx)
- Modify: `bot/src/index.ts` (Twilio async `.catch` sends a best-effort fallback)
- Test: `bot/src/formatter` covered indirectly; add an assertion in `bot/src/openai-analyzer.test.ts` that the retry helper exists is not needed — see Step notes.

**Interfaces produced:** `overloadedMessage(): string`.

- [ ] **Step 1: Add `overloadedMessage` to `formatter.ts`:**
```ts
export function overloadedMessage(): string {
  return "⏳ I’m a bit overloaded right now — please resend your message in a minute and I’ll finish your read.";
}
```

- [ ] **Step 2: Best-effort fallback in `index.ts`** — import `overloadedMessage` from `./formatter.js`, and in the Twilio async branch `.catch`, after logging, attempt a fallback send:
```ts
          .catch((error) => {
            console.error(JSON.stringify({
              level: "error",
              event: "twilio_async_processing_failed",
              message: error instanceof Error ? error.message : String(error),
            }));
            void sendTwilioWhatsApp(config, plan.channelTo, plan.channelFrom, overloadedMessage()).catch(() => {});
          });
```

- [ ] **Step 3: Retry-with-backoff in `openai-analyzer.ts`** — wrap the `fetch` so a single 429/5xx is retried once after a short delay. Replace the `const response = await fetch(...)` call with:
```ts
  let response = await fetch("https://api.openai.com/v1/responses", requestInit);
  if (!response.ok && (response.status === 429 || response.status >= 500)) {
    await new Promise((r) => setTimeout(r, 800));
    response = await fetch("https://api.openai.com/v1/responses", requestInit);
  }
```
where `requestInit` is the existing `{ method, headers, body }` object hoisted into a const just above. (analysis failures are already caught in `analyzer.ts` and fall back to heuristics — keep that.)

- [ ] **Step 4: Build + run** — `npm run bot:test`. Expected: all suites pass (no behavior change offline; this is resilience).

- [ ] **Step 5: Commit**
```bash
git add bot/src/formatter.ts bot/src/openai-analyzer.ts bot/src/index.ts
git commit -m "Never go silent: fallback message + OpenAI retry on 429/5xx"
```
